# Harness spec packs

Dated, reviewed snapshots of each harness's agent-config surface, one file
per harness (`claude.md`, `codex.md`, `devin.md`, `opencode.md`). These are
the evidence behind the emitters in `agent/tools/lib/emit-*.sh`:

- Phase A (the `loom` skill) refreshes a pack when a harness releases a
  config change — live docs first (context7 per repo rule, then web),
  live probes when the docs are ambiguous.
- Phase B (`agent/tools/loom.sh`) is deterministic and never reads these
  files at runtime; the packs justify what the emitters hardcode.

Every claim in a pack carries a source URL or a reference to the live
conformance run (`agent/HARNESS-CONFORMANCE.md`, 2026-09-03). A pack older
than 30 days prints a staleness warning in `make lint` (non-blocking —
refreshing is a Phase A decision, not a commit blocker).

`GAPS.md` here is generated by loom on every run: anything the canonical
config expresses that a harness cannot, with the compensating control.
