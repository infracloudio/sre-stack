# AGENTS.md — sre-stack context

Keep this to one page. Add a correction when agents repeat a mistake.

## Purpose and map

This YAML/bash glue repo provisions robot-shop and hotrod, observability
(Prometheus, Grafana, Loki, Tempo, Beyla, Caretta), and SRE fault scenarios on
AWS EKS or local k3d. Application code comes from upstream images.

- `makefile` orchestrates every lifecycle action; `.env` is the shared config.
- `infra/` provisions clusters/databases and contains the idempotent scripts.
- `app/`, `monitoring/`, `scenarios/` contain workloads, tooling, and faults.
- `agent/` contains source-of-truth policies, hooks, conformance tests, and loom.
- `specs/<nnn>-<slug>/` contains each story's `spec.md`, `plan.md`, `tasks.md`.
- `.specify/` and cross-harness `speckit-*` commands are generated by Specify
  CLI; refresh with `specify init` / `specify integration install`, never edit.
- `.codex/`, `.devin/`, `opencode.json`, and `agent/harness-specs/GAPS.md` are
  generated by `agent/tools/loom.sh` from `.mcp.json`, Claude settings, and loom
  emitters. Change those sources and rerun loom; never edit adapters directly.

## Commands and conventions

- `make setup` / `make cleanup`: EKS lifecycle.
- `make setup-local` / `make cleanup-local`: full k3d lifecycle.
- `make get-service-endpoints`: application and dashboard URLs.
- `make install-check` then `make install`: preview/bootstrap developer tools.
- `make hooks`: enable pre-commit hooks for this clone.
- `make lint`: secrets, protected paths, ratchets, shell/YAML/Helm lint, and loom
  drift. Run it for every change and report its actual output.
- Pin Helm installs and use `*/chart-values/`, not inline `--set` chains except
  one-off host wiring. Preserve existing image/chart pins.
- Scripts resolve the repo root, source `.env`, and check before creating.
- Workloads select `workload=app|persistent|o11y|loadgen` and tolerate taints.
- StorageClass is `gp2`; secrets come from `.env`, never manifests or scripts.

## SDLC contract

Full process: `docs/sdlc/framework.md`. Author and approver must differ.

1. Owner files one 1–2 day story with Problem / Outcome / Out of scope / Must
   keep working (`intent`). Sponsor accepts it (`intent:accepted`).
2. Owner runs `/speckit.specify` then `/speckit.clarify`; no
   `[NEEDS CLARIFICATION]` may remain. Architect approves (`gate:spec-approved`).
3. Builder uses a separate worktree for `/speckit.plan`, `/speckit.tasks`, and
   `/speckit.analyze`. Architect approves (`gate:plan-approved`). CI blocks any
   change outside the story's `specs/` folder before this label.
4. Builder runs `/speckit.implement`; plan departures and reasons go into
   `plan.md` in the same commit. Attach verification output (`evidence:attached`).
5. Agent review ranks findings; an independent human approves; squash-merge
   with the story's `specs/` folder.
6. Run `/speckit.converge` on `main`; fix same-day gaps or file new stories.

Changes require an accepted story and `gate:plan-approved`; informational
questions do not. Do not invent scope or weaken tests, hooks, lint, or CI.

## Grounding and verification

- Query `aws-knowledge` and `microsoft-learn` for AWS/Azure facts.
- Query `context7` for current library/tool documentation.
- Use only MCP servers in `agent/policies/allowed-mcp-servers.md`.
- Run `helm template` or `helm lint` for chart changes. Run `make setup-local`
  only when explicitly asked for a live deployment.

## Repeated traps

- The file is lowercase `makefile`.
- `.env` is deliberately tracked with demo credentials; do not untrack it.
- scenario-02 intentionally degrades RDS; do not repair it.
- Root `values.yaml` is stray and unused.
