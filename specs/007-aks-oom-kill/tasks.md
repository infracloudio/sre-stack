**Goal**: One command makes the cart pod run out of memory and be killed by the cluster until reverted, and checks its own result (FR-001, FR-004, FR-005, FR-006, FR-009).

**Independent Test**: On the running AKS shop, run start, then status; the cart pod shows `OOMKilled` and `RESULT: fault active`.

- [X] T003 [US1] In `infra/azure/scenario-02/cart-oom-kill.sh` replace the start stub: classify with the T002 classifier; row 3 → change nothing, `RESULT: fault already active`, exit 0; rows 1, 2 and 4 → `k set resources deployment/cart -n "$APP_NS" -c cart --requests=memory=8Mi --limits=memory=24Mi` (research Finding 1; requests come down with the limit or the API server rejects it; `-c cart` and memory only, so CPU and every other container keep their values, FR-006), then `k annotate deployment/cart -n "$APP_NS" sre-stack/oom-fault=active --overwrite` (allowance first, marker second, so a half-finished run is a row the commands already handle). Timeout → print each cart pod's `restartCount`, `state` and `lastState`, then `RESULT: the allowance is lowered but no out-of-memory kill was observed within 60s; state when last seen: …`, exit 1, fault left in place so revert can remove it (contracts §3, §4).
